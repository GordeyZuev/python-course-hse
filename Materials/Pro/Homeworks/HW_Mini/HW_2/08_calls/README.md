#### **№8. Заказ с заменой. · 0.9 балла**

Сделаем небольшую модель выдачи заказов в кофейне. Генератор объявляет очередной напиток, а оператор может сообщить, что его приготовить не получится. Напишите `calls(iterable)`: обычный `next` выдаёт заказ, а `throw(ValueError(...))` во время паузы на этом заказе выдаёт запасной напиток `"вода"`.

```python
orders = calls(["латте", "чай"])
next(orders)                          # -> латте
orders.throw(ValueError("нет молока"))  # -> вода
next(orders)                          # -> чай
```

`throw` возвращает воду отдельным результатом: уже полученная строка `"латте"` никуда не исчезает. Следующий обычный `next` продолжает исходную очередь.

**Уточнения.**

- Пустой источник ничего не выдаёт. До первого `next` источник не читается; следующий заказ заранее не берётся.
- Перехватывается только `ValueError`, присланный в паузу на обычном заказе. Другие ошибки выходят наружу и завершают генератор.
- Замена последнего заказа тоже выдаёт воду, затем обход заканчивается.
- Если бросить ошибку, пока генератор стоит на выдаче воды, она выходит наружу: повторную замену не делаем.
- Ошибка самого источника выходит наружу. Два вызова `calls` работают независимо.

## **Как это сделать.**

Обязательно поставьте `yield` обычного заказа внутри `try` / `except` с указанным типом исключения. Перехватывайте только `ValueError`, остальные ошибки пропускайте наружу. В обработчике выдайте воду ещё одним `yield`.
