#### **№13. Хрупкая функция. · 1 балл**

**1 балл.**

У функции есть запас жизней. Напишите декоратор `fragile(n)`: `n` – сколько падений ещё можно показать. Каждое падение из короткого списка тратит одну жизнь, и эта ошибка выходит наружу как есть. Когда запас кончился, тело больше не запускается: любой следующий вызов возвращает строку `Функция сломана`.

`@fragile(4)` падает по-настоящему четыре раза. Следующий вызов после этих четырёх падений возвращает фразу.

Жизнь тратят только `ValueError`, `TypeError` и `RuntimeError`. Любая другая ошибка, например `KeyError`, тоже выходит как есть, но жизнь не тратит.

**Уточнения.**

- Удачный вызов жизнь не тратит и возвращает свой результат. Успех между падениями тоже жизнь не тратит.
- Пока жизнь есть, пойманная ошибка выходит с тем же типом и тем же текстом. Как поднять её дальше: [Raising exceptions](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Типы: [ValueError](https://docs.python.org/3/library/exceptions.html#ValueError), [TypeError](https://docs.python.org/3/library/exceptions.html#TypeError), [RuntimeError](https://docs.python.org/3/library/exceptions.html#RuntimeError).
- Когда жизней не осталось, тело не стартует. Даже удачный вызов возвращает `Функция сломана`.
- `n = 0` – уже первый вызов не входит в тело и отдаёт эту фразу.
- Пока функция жива, аргументы доходят до тела, в том числе по имени.
- В момент декорирования функция не вызывается.

`__name__` и `__doc__` остаются от исходной функции. Возьмите `functools.wraps`. Две обёрнутые функции не делят запас жизней.

Своего класса исключения нет.

```python
@fragile(2)
def take(kind):
    if kind == "пробой":
        raise ValueError("пробой")
    return kind

take("ночь")     # -> ночь
take("пробой")   # ValueError: пробой
take("пробой")   # ValueError: пробой
take("утро")     # -> Функция сломана
```

## **Как это сделать.**

Замыкание помнит, сколько жизней ещё осталось. Если запас кончился, верните `Функция сломана` и не вызывайте тело. Иначе вызовите тело. `ValueError`, `TypeError` и `RuntimeError` поймайте, потратьте жизнь и снова поднимите через `raise`. Другую ошибку не ловите: она выйдет сама и жизнь не потратит.
