## **С чего начать.**

Скачайте репозиторий курса целиком и откройте его папку в редакторе. В папке каждой задачи есть условие `README.md`, файл решения (например, `HW_1/01_line/line.py` внутри `HW_Mini`) и `test.py`. Замените `...` в файле решения своим кодом, сохранив имена функций и параметры из условия. Тесты и служебные файлы менять не нужно.

Команды ниже выполняйте в терминале, а не в Python-консоли или ячейке ноутбука. Из корня репозитория перейдите в папку ДЗ:

```bash
cd Materials/Pro/Homeworks/HW_Mini
```

В Windows cmd: `cd Materials\Pro\Homeworks\HW_Mini`.

## **Среда с нуля.**

Нужен установленный Python 3.10 или новее. Окружение и `requirements.txt` общие для обеих работ и лежат в `HW_Mini`. Команды этого раздела запускайте оттуда. Создайте окружение и установите зависимости один раз; в новом терминале достаточно снова его активировать.

### **macOS и Linux.**

Проверьте версию командой `python3 --version`: нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### **Windows.**

Проверьте версию командой `py -3 --version`: нужен Python 3.10 или новее. Создайте окружение:

```bat
py -3 -m venv .venv
```

Если `py` нет, проверьте `python --version` и создайте окружение командой `python -m venv .venv`.

Активируйте его командой для своего терминала:

- **cmd:** `.\.venv\Scripts\activate.bat`
- **PowerShell:** `.\.venv\Scripts\Activate.ps1`

Если PowerShell запрещает запуск скрипта активации, откройте cmd и используйте команду для него.

После активации установите зависимости:

```bash
python -m pip install -r requirements.txt
```

## **Как прогнать тесты.**

Все задачи, из этой папки:

```bash
python -m pytest
```

Одна задача из её папки:

```bash
python test.py
```

Одна задача из этого корня, на примере эфирной строки:

```bash
python -m pytest HW_1/01_line/test.py
```

При запуске через `pytest` итог `passed` означает, что проверки прошли; `FAILED` – проверка нашла ошибку. Откройте блок этого теста выше итоговой строки: там показаны проверяемый вызов и причина сбоя. При `ERROR` проверка не смогла запуститься – сначала прочитайте сообщение об ошибке, например о синтаксисе или отсутствующем модуле. При запуске `python test.py` успешная проверка печатает сообщение, что тесты прошли.

До решения задач ошибки ожидаемы: в заготовках стоит `...`. Проверяйте сначала одну задачу, после исправления сохраняйте файл и запускайте её тесты заново. Если `python` сообщает `No module named pytest`, активируйте окружение и установите зависимости из `requirements.txt`.

## **Отчёт баллов.**

Если проверка одной задачи не завершается за 10 секунд, грейдер сообщает об этом и переходит к следующей. Так бесконечный цикл в одном решении не остановит весь отчёт.

`grade.py` лежит в `Other/tools/`. Команды ниже запускайте из корня репозитория курса: активируете окружение этой папки и запускаете грейдер. Он запускает каждый `test.py` отдельным процессом и не подменяет файлы решения. Задача получает полный балл, если её тесты прошли, иначе – 0. Отчёт показывает баллы; чтобы увидеть причину ошибки, запустите тесты этой задачи отдельно. Для HW 1 он показывает обязательные баллы, бонусы и итог с потолком 10; для HW 2 – сумму баллов из 10.

### **macOS и Linux.**

```bash
source Materials/Pro/Homeworks/HW_Mini/.venv/bin/activate
python Other/tools/grade.py
```

### **Windows.**

Из корня репозитория активируйте окружение:

- **cmd:** `.\Materials\Pro\Homeworks\HW_Mini\.venv\Scripts\activate.bat`
- **PowerShell:** `.\Materials\Pro\Homeworks\HW_Mini\.venv\Scripts\Activate.ps1`

Затем запустите:

```bash
python Other/tools/grade.py
```
