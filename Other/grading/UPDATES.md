# Обновление курса через Git

| Источник | Назначение | Ветка |
|---|---|---|
| `origin` – ваш приватный репозиторий | Решения, новые заготовки и настройки проверки | `main` |
| `upstream` – общий репозиторий курса | Условия, тесты, лекции и исправления | `course_2026` |

## Настроить один раз

Примите приглашение GitHub. Откройте свой приватный репозиторий и скопируйте
адрес через **Code → HTTPS**. В терминале выполните:

```bash
git clone АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ
cd ИМЯ_ВАШЕГО_РЕПОЗИТОРИЯ
```

В его папке проверьте адреса:

```bash
git remote -v
```

`origin` должен указывать на ваш репозиторий в `ai-hse-python`.
Если `upstream` ещё нет, добавьте его:

```bash
git remote add upstream https://github.com/GordeyZuev/python-course-hse.git
```

Настройте объединение изменений для этого репозитория:

```bash
git config --local pull.rebase false
git config --local pull.ff true
```

## Получить обновления

Перейдите в ветку `main`, выполните `git status` и сохраните свою работу
локальным коммитом, если есть незакоммиченные изменения.
Затем выполните команды по очереди. Если возникла ошибка, устраните её
до перехода к следующей команде.

```bash
git pull --no-edit origin main
git pull --no-edit upstream course_2026
```

Команды выполняются в ветке `main`. Сначала обновляется ваш репозиторий,
затем общие материалы. **Push после этого не нужен:** пока изменилась только
локальная копия, попытки не расходуются.

Для нового ДЗ сначала дождитесь объявления о выдаче, затем получите оба источника
и начинайте решать. Преподаватель доставляет заготовки в origin до включения
проверки. Если начать решение раньше обновления, может возникнуть конфликт `add/add`.

## Отправить решение

Сохраните изменения файлов решения коммитом. Например, для одной задачи HW 1
из корня репозитория:

```bash
git add Materials/Pro/Homeworks/HW_Mini/HW_1/01_line/line.py
git commit -m "Solve HW 1 task 1"
```

Добавьте аналогично остальные файлы решений, которые готовы сдать. Затем
[получите обновления](#получить-обновления) и
[проверьте решение локально](README.md#обновиться-и-проверить-решение).
Если после проверки исправили код, добавьте изменения и создайте ещё один коммит.
Перед отправкой проверьте, какие файлы будут отправлены:

```bash
git diff --name-only origin/main HEAD
```

Посмотрите список файлов. Если там есть решения двух ДЗ, отправка потратит
по попытке каждого. Когда готовы сдавать:

```bash
git push origin main
```

Учитывается вся разница с origin, а не только последний коммит. Push с README
тоже будет сдачей, если вместе с ним отправляются ранее не отправленные решения.
Push только условий или тестов попытку не расходует.

## Частые проблемы

**Ситуация:** ссылка из приглашения открывает страницу 404.

**Решение:** войдите в GitHub под аккаунтом, который указали преподавателю.
Откройте `https://github.com/ai-hse-python/hse_python_26_ВАШ-ЛОГИН/invitations`,
подставив свой логин, и примите приглашение. Если страница не открывается,
сообщите ассистенту свой логин.

**Ситуация:** Git не даёт обновиться из-за незакоммиченных изменений.

**Решение:** сохраните работу локальным коммитом и повторите обновление.

**Ситуация:** Git сообщает о конфликте слияния (`merge conflict` или `add/add`).

**Решение:** выполните `git status` и откройте указанные файлы. Исправьте
конфликт, сохранив своё решение. Затем выполните `git add` для исправленных
файлов и `git merge --continue`. Если открылся редактор Vim, сохраните сообщение
и выйдите командой `:wq`. Если хотите отменить слияние, выполните
`git merge --abort`: ранее сохранённые коммиты останутся.

**Ситуация:** Git отклонил отправку (`push rejected` или `non-fast-forward`).

**Решение:** выполните `git pull --no-edit origin main`, проверьте список файлов
из раздела отправки и повторите `git push origin main`. Не используйте `push --force`.

**Ситуация:** Git пишет, что `upstream` не существует.

**Решение:** добавьте его один раз и повторите обновление:

```bash
git remote add upstream https://github.com/GordeyZuev/python-course-hse.git
```

Если `upstream` уже есть, но адрес неверный, исправьте его:

```bash
git remote set-url upstream https://github.com/GordeyZuev/python-course-hse.git
```

**Ситуация:** локальные тесты проходят, а результат в Actions отличается.

**Решение:** обновите материалы и повторите локальную проверку. Actions использует
версию тестов, подключённую преподавателем; её обновление может занять время.
Если расхождение осталось, отправьте ассистенту ссылку на запуск.

**Ситуация:** после push проверка не запустилась или завершилась с ошибкой.

**Решение:** проверьте, что отправили изменения файлов решения в ветку `main`.
Откройте запуск в Actions и его Summary. Если запуска нет или результата нет,
отправьте ассистенту ссылку на репозиторий или запуск.

**Ситуация:** результат есть в Actions, но его нет в Issue.

**Решение:** дождитесь обновления ведомости – оно происходит раз в день.
Если результат не появился, отправьте ассистенту ссылку на запуск.

**Ситуация:** попытки закончились или проверка сломалась.

**Решение:** обратитесь к ассистенту и приложите ссылку на запуск. Повторный
запуск той же проверки не создаёт новую попытку; новый push с решением создаёт.
