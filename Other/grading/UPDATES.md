# Обновление курса через Git

| Источник | Назначение | Ветка |
|---|---|---|
| `origin` – ваш приватный репозиторий | Решения, новые заготовки и настройки проверки | `main` |
| `upstream` – общий репозиторий курса | Условия, тесты, лекции и исправления | `course_2026` |

## Настроить один раз

Примите приглашение GitHub и клонируйте свой приватный репозиторий.
В его папке проверьте адреса:

```bash
git remote -v
```

`origin` должен указывать на ваш репозиторий в `ai-hse-python`.
Если `upstream` ещё нет, добавьте его:

```bash
git remote add upstream https://github.com/GordeyZuev/python-course-hse.git
```

Настройте объединение изменений для этого репозитория:

```bash
git config --local pull.rebase false
git config --local pull.ff true
git config --local merge.autoEdit no
```

## Получить обновления

Выполните `git status` и сохраните свою работу локальным коммитом.
Затем выполните команды по очереди. Если возникла ошибка, устраните её
до перехода к следующей команде.

```bash
git pull origin main
git pull upstream course_2026
```

Команды выполняются в ветке `main`. Сначала обновляется ваш репозиторий,
затем общие материалы. **Push после этого не нужен:** пока изменилась только
локальная копия, попытки не расходуются.

Для нового ДЗ сначала дождитесь объявления о выдаче, затем получите оба источника
и начинайте решать. Преподаватель доставляет заготовки в origin до включения
проверки. Если начать решение раньше обновления, может возникнуть конфликт `add/add`.

## Отправить решение

[Проверьте решение локально](README.md#обновиться-и-проверить-решение) и сохраните
его коммитом. Перед отправкой получите последние изменения origin:

```bash
git pull origin main
git diff --name-only origin/main HEAD
```

Посмотрите список файлов. Если там есть решения двух ДЗ, отправка потратит
по попытке каждого. Когда готовы сдавать:

```bash
git push origin main
```

Учитывается вся разница с origin, а не только последний коммит. Push с README
тоже будет сдачей, если вместе с ним отправляются ранее не отправленные решения.
Push только условий или тестов попытку не расходует.

## Troubleshooting – частые проблемы

**Незакоммиченные изменения.** Сохраните работу локальным коммитом и повторите обновление.

**Merge conflict / add/add.** Выполните `git status`, исправьте конфликтующие файлы,
сохранив своё решение, затем выполните `git add` для них и `git merge --continue`.
Чтобы отменить слияние, используйте `git merge --abort`: ранее сохранённые коммиты останутся.

**Push rejected / non-fast-forward.** Повторите команды из раздела отправки,
проверьте результат и снова сделайте push. `push --force` не нужен.

**Неверный адрес upstream.** Исправьте его:

```bash
git remote set-url upstream https://github.com/GordeyZuev/python-course-hse.git
```

Если локальные тесты и Actions дают разные результаты, обновите материалы.
Официальная проверка использует версию тестов преподавателя. Если расхождение
осталось, сообщите ему ссылку на запуск.

**Проверка не запустилась.** Проверьте, что push отправлен в `main` и содержит
изменения файлов решения. Если запуск есть в Actions, откройте его Summary.

**Попытки закончились или произошёл технический сбой.** Обратитесь к ассистенту
и приложите ссылку на запуск в Actions. Повторный запуск той же проверки
не создаёт новую попытку.
