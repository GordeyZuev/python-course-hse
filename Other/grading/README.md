# Сдача домашних работ

У вас один приватный репозиторий на весь курс. Работайте в ветке `main`,
меняйте файлы решений и сохраняйте их исходные пути. Условия, тесты,
`homework.json` и настройки проверки обновляют преподаватели.

## Как всё устроено

Общий репозиторий курса содержит условия и тесты. В своём приватном
репозитории вы храните и сдаёте решения. Получайте обновления из обоих
репозиториев по [инструкции](UPDATES.md).

Когда вы отправляете изменения решения через `git push`, GitHub Actions
запускает проверку всего ДЗ. Она берёт ваши файлы решений и опубликованную
преподавателем версию тестов. Баллы и результаты задач появляются в Summary
запуска, а затем попадают в Issue «Оценки и проверки». После дедлайна работу
смотрит ассистент и при необходимости меняет итоговую оценку с комментарием.

## Попытки и оценки

- На каждое ДЗ – **четыре попытки**. Push с изменёнными решениями запускает
  проверку ДЗ целиком. Если затронуты два ДЗ, расходуется по попытке каждого.
- Локальные коммиты, тесты и получение обновлений попытки не расходуют.
- В зачёт идёт лучший общий результат одной своевременной попытки.
- Если попытки остались, после дедлайна тесты покажут результат по каждой задаче,
  но балл за позднюю попытку будет **0 / 10**. Например, если до дедлайна вы
  получили 8 баллов, а после дедлайна тесты показали 10, в зачёте останутся 8.
  Если своевременной сдачи нет, автоматический балл будет 0.
- Пятая и последующие попытки тесты не запускают. Если это произошло,
  свяжитесь с ассистентом.

Временем сдачи считается время создания запуска в GitHub. Завершиться проверка
может после дедлайна. При техническом сбое обратитесь к преподавателю:
повторный запуск той же проверки новую попытку не создаёт.

## Обновиться и проверить решение

Перед новым ДЗ или после исправления тестов выполните
[обновление через Git](UPDATES.md). Начинайте новое ДЗ после объявления о выдаче.

Локальная проверка из корня курса, в настроенном Python-окружении:

```bash
python Other/tools/grade.py --hw pro-hw1
```

Для другого ДЗ используйте его `id` из `homework.json`. Там же указаны дедлайн,
баллы и зависимости для локальной установки. Без `--hw` проверяются все включённые ДЗ.

## Посмотреть результат

После push откройте **Actions → Submit код-ДЗ → нужный запуск → Summary**
в своём репозитории и дождитесь завершения проверки. Ведомость и Issue «Оценки и
проверки» обновляются примерно раз в три часа; возможна задержка GitHub.
После дедлайна ассистент проверяет работу. Его оценка имеет приоритет над автоматической.
