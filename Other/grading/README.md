# Сдача домашних работ

Каждому студенту выдаётся один приватный репозиторий на курс. Решения загружайте
в него, в `main`, сохраняя исходные пути файлов. Меняйте только файлы решений.
Тесты, условия и workflow поддерживают преподаватели.

Каждый push с изменёнными решениями — сдача соответствующего ДЗ целиком.
На каждое ДЗ четыре попытки. Push, затрагивающий два ДЗ, расходует по одной
попытке каждого. В зачёт идёт лучший общий результат одной попытки.
Не отправляйте промежуточные решения на GitHub, если не готовы тратить попытку:
локальные коммиты и тесты ограничений не имеют.

Сразу после push откройте Actions → Submit <код ДЗ> → Summary
(например, Submit pro-hw1).
Официальная ведомость и Issue «Оценки и проверки» обновляются раз в три часа,
иногда позднее из-за очереди GitHub. Срок определяется временем создания
запуска GitHub, не временем коммита и не временем обновления ведомости.
Проверка, принятая вовремя, может завершиться после дедлайна.

Повторный запуск той же проверки не создаёт новую попытку. Не удаляйте и не
изменяйте workflow: такой результат не принимается. Удаление истории запусков
не возвращает попытки. При техническом сбое обратитесь к преподавателю.

## Обновление курса

Работайте в клоне своего приватного репозитория: `origin` должен указывать
на него. Проверьте адреса командой `git remote -v`.
Один раз настройте общий источник (если `upstream` уже есть, повторять не нужно):

```bash
git remote add upstream https://github.com/GordeyZuev/python-course-hse.git
```

Сохраните свои изменения локальным коммитом — он не запускает проверку.
Переключитесь на `main`, где находятся ваши решения, и получите обновления:

```bash
git switch main
git fetch origin
git merge origin/main
git fetch upstream
git merge upstream/course_2026
```

Сначала подтягиваются обновления вашей репы (в том числе настройки проверки),
затем материалы курса. После каждой команды проверяйте результат: если возник
конфликт, разрешите его и завершите merge перед следующей командой.
Если вы не готовы разрешать конфликт, `git merge --abort` отменяет текущий merge.
Не заменяйте свои решения заготовками преподавателя при разрешении конфликтов.

Эти команды обновляют только локальную копию. Отдельный push сразу после
обновления не нужен: отправляйте изменения, когда готовы сдавать решение.
Push только README и тестов не расходует попытки. Если push меняет хотя бы один
отслеживаемый файл решения относительно `origin/main`, он запускает сдачу:
это относится и к добавленным заготовкам нового ДЗ. Наличие локальных коммитов
с ещё не отправленными решениями также учитывайте перед push.

Обновления тестов для официальной проверки включает преподаватель отдельно.
Получение новых тестов через Git само по себе не переключает версию проверки
в Actions и не пересчитывает предыдущие результаты.

## Локальная проверка

Из корня курса, в настроенном Python-окружении:

```bash
python Other/tools/grade.py --hw pro-hw1
python Other/tools/grade.py --hw pro-hw2
```

После дедлайна ассистент проверяет зафиксированную лучшую сдачу и публикует
итог в Issue. Ручной итог имеет приоритет над автоматическим.
